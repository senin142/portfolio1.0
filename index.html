01 · About

From front end to full ownership

I started as a front-end developer in April 2022, building responsive, SEO-optimized sites in React and Next.js for clients including CNBC Arabia, World Climate Institute, and Mazars. Since 2024 I've moved deep into the backend and infrastructure side of the CNBC Arabia platform — designing the platform's core NestJS microservices architecture (a dual-controller-per-domain pattern with shared authentication, DTO, and error-handling libraries reused across independently-deployable services), PostgreSQL schema and data migrations, third-party API integrations, and Google Cloud infrastructure. I now lead a team of 5–6 engineers, including a new TV app initiative, having grown from individual contributor to technical lead within the same organization over 4+ years.

Recent work spans a 40+ table PostgreSQL schema migration (one table exceeding 50,000 records), building an analytics ingestion pipeline against the Meta Graph and YouTube APIs, and resolving 100+ bugs across backend and frontend — from colorspace mismatches in live video to race conditions in file uploads. I like owning problems end-to-end: from the database schema to the deployed, monitored service.

Things I've built and shipped

Deployed

Bilingual content data model

Designed and migrated 40+ PostgreSQL tables — including one exceeding 50,000 records — generating DDL from Sequelize-TypeScript entities, resolving foreign-key constraints, and bulk-loading bilingual Arabic/English content.

Challenge: bulk-loading into the 50,000+ row table while keeping foreign keys intact meant migrations had to run in a strict dependency order — a failure partway through left tables in an inconsistent state. Next time: I'd script that ordering and add automated FK-integrity checks up front, instead of resolving constraint failures migration by migration.

In staging

Meta + YouTube analytics ingestion

Building an ingestion pipeline covering one Facebook, Instagram, and YouTube account, ahead of production rollout. Designed a shared ingestion-runs tracking table and a remediation roadmap — idempotency constraints and Cloud Tasks orchestration.

Challenge: Meta Graph and YouTube Data each have their own rate limits, pagination, and failure modes, which made a single shared abstraction harder to get right on the first pass. Next time: I'd design the shared ingestion-runs table and retry/backoff policy before writing the first platform-specific integration, not after.

Production reliability & bug resolution

Resolved 100+ bugs across backend and frontend, including a BT.601/BT.709 colorspace mismatch causing incorrect livestream colors (web-only, not YouTube), a GCS upload race condition, and an Elasticsearch sort-query bug.

Challenge: the colorspace bug only showed up in the web player, not YouTube's own player, which pointed suspicion at the encoder before the color-matrix handling in playback. Next time: I'd add a colorspace-tagging check earlier in the pipeline so a mismatch surfaces as an automated warning instead of a visual bug report.
